Python was CPython 3.12.13 on macOS arm64. The test-owned Docker container
`django-tasks-p1-20261023` ran PostgreSQL 16.15 (Debian aarch64), with its listener
bound to loopback port 55461. Source, wheel, and sdist suites used separate
`postgres`, `p1_wheel`, and `p1_sdist` database namespaces. No SQLite result is
used as locking evidence. The container and its anonymous storage were removed
after verification; pre-existing containers were left alone.

The locked library environment used Django 6.1.2, psycopg 3.3.6, Tenacity 9.2.1,
Pydantic 2.14.1, boto3 1.43.114, and aws-lambda-powertools 3.36.0.
The wheel minimum lane used Django 6.1, psycopg/binary 3.2.1, Tenacity 8.4.2,
Pydantic 2.12.0, boto3 1.40.0, and aws-lambda-powertools 3.35.0.
The latest sdist lane resolved Django 6.1.2, psycopg/binary 3.3.6, Tenacity 9.2.1,
Pydantic 2.14.1, boto3 1.43.118, and aws-lambda-powertools 3.37.0.
These are two specific CPython 3.12/PostgreSQL cells, not the full advertised matrix.

The minimum lane initially failed before test collection because Tenacity 8.4.0's
wheel omits `tenacity.asyncio`. This matches the
[upstream packaging report](https://github.com/jd/tenacity/issues/475) and
[patch release history](https://github.com/jd/tenacity/releases/tag/8.4.1).
The bound is now 8.4.2, also including its subsequent context-handling fix.
The psycopg bound is now 3.2.1, matching the existing verifier's first-installable
binary-extra decision. The corrected minimum lane passes. Earlier local failures
from missing metric registration, renamed traceability assignments, test enum
spelling, and admin tuple annotations were corrected before final verification.

## Artifacts and reproduction

JUnit reports and artifact identities are retained locally under
`artifacts/p1-2026-10-23/` (ignored test output, not committed release receipts).
Built distributions are under `/private/tmp/django-tasks-p1-dist/`.
The identity JSON records SHA-256 hashes for the tested distribution bytes.
The final documentation/backlog execution record was written after the tested
artifacts were built; this working tree therefore needs a fresh candidate build
and source digest before any release gate.

Representative commands, with disposable database connection variables set:

```sh
uv sync --locked --all-packages --all-groups --all-extras
make check
REQUIRE_POSTGRES=1 uv run pytest --junitxml=/private/tmp/p1-library.xml
uv run --directory examples/sample_project pytest -m 'not browser'
uv build --out-dir /private/tmp/django-tasks-p1-dist
uv run python scripts/verify_installed.py --dist /private/tmp/django-tasks-p1-dist \
  --artifact wheel --dependency-bounds minimum --report /private/tmp/p1-installed-wheel-minimum.xml
uv run python scripts/verify_installed.py --dist /private/tmp/django-tasks-p1-dist \
  --artifact sdist --report /private/tmp/p1-installed-sdist-final.xml
uv run sphinx-build -b html docs /private/tmp/django-tasks-p1-docs -W --keep-going
terraform -chdir=terraform/modules/task_system test
```
